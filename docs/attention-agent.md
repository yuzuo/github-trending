# 项目动态分析与需要关注

入口：`/crawler-watch/attention`。先关注项目，再填写使用状态、版本、场景和依赖能力。未填写版本时，影响明确保持未知。档案中的版本、场景与能力会发送给现有 `TRANSLATION_*` 配置的模型；私人项目笔记不发送。

模型整理变化摘要、影响、建议行动和证据引用。页面默认显示已分析的高、中优先级事件，可勾选全部查看待分析、失败或过期记录。所有模型结论都标为未验证。Issue 关闭、维护者回复、PR 合并与修复版本发布不是同一个状态。

开启现有调度后，每小时最多分析 5 个关注项目，每项目一条事件。新事件和内容变化优先；已有结果六小时后按最早分析时间轮换刷新，失败自动等待 24 小时，手动刷新可重试失败。项目很多或积压较多时有排队延迟。模型与采集共用任务锁。

证据包括原始动态、正文最多 3 个同仓库引用、Issue 首尾页中的维护者回复以及根目录 CHANGELOG.md。中间页、省略评论、默认分支日志和 GitHub 限流会显示证据限制。该版本没有穷尽所有 PR、文档变更，也没有将相关来源推断为同一问题；相关已保存动态以链接关联。

档案或来源变化会使分析失效；证据刷新后才形成新分析。模型返回必须符合结构且只能引用实际提供的证据 ID。原文仅作为数据，不执行其指令。具体能力是否有效仍由独立固定测试或人工复核确定。

Scrapy 测试结果在选择项目档案后显示，运行与导入见 [固定任务说明](scrapy-validation.md)。当前没有自动执行任意开源仓库代码，也没有新版本发布后自动触发测试。
