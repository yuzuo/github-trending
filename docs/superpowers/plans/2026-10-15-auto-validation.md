# 关注项目自动版本测试实施计划

> 执行方式：superpowers:executing-plans，当前会话逐步实现并验证。用户已授权发现版本、隔离测试、对比结果、回归提示，并要求覆盖关注项目。

**目标：** 所有当前及以后关注的公开项目，在监测发现正式 Release 后进入自动检查；Scrapy 运行原有固定功能任务，所有项目运行源码基础检查。基础检查不冒充采集能力验证。

**架构：** 新表保存唯一任务及重试租约。API 调度只入队、不访问 Docker socket。Mac 主机独立 Python 执行器通过本地 Docker Compose 管理命令领取和提交任务，容器内禁网运行测试。跟踪队列、来源版本、源码 SHA256、任务指纹和结果，页面独立展示，无需模型成功才能看到回归。

**范围说明：** 每项目首次只回填最近两个正式版本，随后按本地发现变化时间处理版本（避免漏掉较晚发现的已发布版本）；草稿/预发布不触发，没有 Release 显示等待。所有项目默认基础检查，Scrapy 同时功能测试。基础检查仅解析归档中的 Python 源码和 JSON 项目清单，既不安装项目依赖也不运行其代码；不支持的语言显示覆盖不足。源码检查的失败是当前 Python 环境下的语法/清单问题，不能称为业务能力退化。登录、真实平台、浏览器等能力需后续专用任务。

- [ ] `backend/app/models.py`、`validation_jobs.py`：新增任务和启用记录，唯一键、租约、取消关注、错误重试、严格完成结果校验与对比。测试重复入队、预发布排除、初次回填、并发领取、租约到期、取消关注、错误与回归区分。
- [ ] `backend/app/main.py`、`attention_api.py`：调度入队、只读任务概览、同源手动重试；既有结果保留。
- [ ] `validation/source_suite.py`、`worker.py`：有界归档检查、下载限定 GitHub codeload、固定 Docker 配置；资源限额、超时清理、日志留存。单测恶意归档/输出、项目身份与版本、环境可比性。
- [ ] `frontend/src/Attention.vue`：所有关注项目的覆盖、任务状态及回归提醒；显示功能测试待配置、无版本、执行错误。DOM 测试保证与模型分析独立、失败不会显示通过。
- [ ] 本地全量测试、多个真实项目执行；备份并部署 23 服务器，安装用户级 launchd 执行器，核对已有数据、任务实际完成与服务健康。

不会给 Web 服务挂载 Docker socket、不会运行来源文字提供的命令、不会以模型声称通过替代实际结果。管理员维护测试适配器。结果版本对比必须同项目、同任务指纹、同 Python 环境；下载、安装、超时为执行错误，不能当功能回归。

## 验收完成

以上实施项已完成，98 后端、22 前端、21 执行器测试通过。多项目真实执行、限流恢复、服务常驻和数据保留均已在线核对。详细记录见 `docs/auto-validation-deployment-2026-10-15.md`。novel-plus 因当前归档限额未完成检查，明确保留执行错误；其他项目的功能实测仍需专用适配器。
