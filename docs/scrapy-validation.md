# Scrapy 固定任务版本对比

运行：`python validation/run.py --versions 2.18.0 2.19.0 --output .local/scrapy-results`。需要 Docker；构建阶段从 PyPI 安装指定稳定版本。执行阶段禁用容器外网、使用非 root 用户、只读文件系统并限制资源。

任务启动容器内本地 HTTP 站点：3 页列表、6 个详情、重复链接，以及第一次返回 503 的第二页。检查翻页、字段准确率、记录去重与失败重试，保留实际记录、访问次数、Scrapy/Python/依赖版本及任务文件 SHA256。

2026-10-15 实测：Scrapy 2.18.0 和 2.19.0 均通过；各得到 6 条正确记录、0 重复、1 次重试。耗时分别为 0.6866 和 0.7598 秒；单次本地固定任务耗时不适合作为性能排名。

管理员在后端环境导入：`python -m app.validation_import /results/2.18.0.json /results/2.19.0.json`。需先存在 scrapy/scrapy 观察项目。重复导入同一文件不产生重复记录。导入检查版本、指标、完成状态与任务指纹；这不是对任意外部报告的密码学认证，应只导入自己执行的结果。

界面只比较任务指纹及预期记录数相同的两个最近稳定版本。旧版本通过、新版本失败会显示固定任务回归。结果不能证明动态页面、登录、反爬应对、断点续采或其他能力；当前为管理员手动执行流程，没有自动新版本触发。
