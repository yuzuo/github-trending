## 1. 产品概述

开源观察是面向个人及可信局域网的小型 GitHub 项目发现与阅读工具。产品每日保存两类榜单及项目资料，帮助用户发现近期热门项目、查阅高 Star 仓库，并回看已经采集的历史快照。

核心价值：

- **发现项目**：分别提供每日 Trending 和累计 Star 总榜，满足趋势发现与成熟项目查找两种需求。
- **降低阅读门槛**：为 Trending 项目提供中文简介和 README 翻译，同时保留原文。
- **保留历史依据**：按日期保存榜单、项目资料及 README，避免历史页面被最新资料替换。
- **本地保存与管理**：通过本地部署积累数据，支持自动采集、手动补齐和采集状态查看。

产品不对项目质量、维护活跃程度或许可证适用性作评价；Star 数是来源数据，不是质量评分。

## 2. 目标用户与使用场景

以下为根据现有功能归纳的目标场景，尚未经过用户调研验证。

| 用户 | 核心需求 | 典型操作 |
| --- | --- | --- |
| 开发者、技术学习者 | 发现近期热门工具并快速理解用途 | 查看 Trending，筛选语言，阅读中文 README |
| 技术选型人员 | 查找关注度较高的公开仓库 | 浏览 Star 总榜，搜索项目，查看原文及源仓库 |
| 开源研究与内容整理人员 | 回看某天保存的项目资料 | 切换历史日期，查看当日排名、Stars 与 README |
| 本地部署维护人员 | 保证采集持续运行并处理失败 | 配置调度与翻译服务，查看状态，补齐失败项 |

上述角色仅用于描述使用需求，当前系统没有账号或角色权限区分。

## 3. 产品范围

### 3.1 当前支持

| 模块 | 能力 |
| --- | --- |
| 每日 Trending | 采集来源页面实际返回的项目，展示新增 Stars 与累计 Stars |
| Star 总榜 | 使用 GitHub Search API 获取累计 Stars 排名前 N 的公开仓库 |
| 快照浏览 | 按来源和日期查看已保存的数据 |
| 搜索与筛选 | 项目名称、描述关键词搜索，以及开发语言筛选 |
| 项目详情 | 展示基本信息、许可证、时间字段与 README |
| 中文阅读 | Trending 简介翻译、README 中文与原文切换 |
| 采集管理 | 定时采集、手动补齐、任务状态、失败重试与限流保护 |

### 3.2 当前不包含

- 登录、用户管理、按账号隔离的收藏、订阅和通知推送（共享关注清单见第 11 节）。
- GitHub 全站实时排名或完整仓库归档。
- 未采集日期的历史榜单恢复。
- 趋势折线图、日期间对比、数据导出及独立分析页面。
- Star 总榜的中文翻译。
- 仓库克隆、项目代码执行或自动质量评估。

## 4. 页面结构与使用流程

### 4.1 页面入口

| 入口 | 用途 |
| --- | --- |
| `/` | 默认展示 Star 总榜 |
| `/stars` | 浏览累计 Star 总榜 |
| `/trending` | 浏览每日 Trending |
| 项目详情弹窗 | 在当前榜单页内阅读所选日期的项目资料 |

两个榜单通过顶部导航切换，各自展示日期列表和最近采集任务。

### 4.2 首次使用

1. 部署服务并完成必要配置。
2. 打开任一榜单页面；尚无数据时展示引导信息。
3. 点击“补齐今日采集”，或等待自动调度。
4. 页面展示采集状态；任务结束后刷新日期和当前列表。
5. 点击项目名称或“阅读项目”打开详情。

### 4.3 日常浏览

1. 选择每日 Trending 或 Star 总榜。
2. 默认查看该来源最新的已保存日期，也可切换历史日期。
3. 输入关键词，或选择开发语言缩小范围。
4. 阅读卡片摘要，打开详情查看 README。
5. 需要进一步了解时，通过 GitHub 链接访问源仓库。

### 4.4 补齐失败内容

1. 查看任务状态、成功/失败数量和错误摘要。
2. 在外部服务恢复或冷却结束后，点击“补齐今日采集”。
3. 系统继续当天已经确定的榜单成员，保留成功记录并处理未完成内容。

**手动按钮始终针对今天。** 浏览历史日期时点击按钮，也不会重新采集该历史日期；已有日期选择不会因此自动切换到今天。

## 5. 功能说明

### 5.1 榜单展示

| 对比项 | 每日 Trending | Star 总榜 |
| --- | --- | --- |
| 数据来源 | GitHub Trending 每日页面及仓库接口 | GitHub Search API 及 README 接口 |
| 覆盖范围 | 来源页面实际返回的项目，数量不固定 | 默认 Top 100，可配置为 1–1000 |
| 排序 | 来源提供的当日新增 Stars 降序，缺失值置后，再按源站排名排序 | 累计 Stars 降序，再按来源排名排序 |
| 排名标签 | 来源排名，可能与页面排序位置不同 | 总榜排名 |
| 简介 | 优先中文，无译文时展示原文 | 原文 |
| README | 可切换中文和原文 | 仅原文 |
| 翻译状态 | 展示相关状态及异常提示 | 不展示翻译操作或状态 |

项目卡片展示仓库名称、简介、语言、许可证、Stars、采集时间和 GitHub 链接。Trending 额外展示来源提供的新增 Stars；来源缺失时显示“未提供”，不当作零。

### 5.2 日期、搜索与筛选

- 日期选项仅来自当前来源已保存的快照，按日期从新到旧排列。
- 名称与描述采用包含式关键词匹配；后端也匹配快照中的中文描述。
- 输入关键词后约 250 毫秒触发搜索；不是对 README 全文搜索。
- 开发语言按所选日期快照中的语言字段精确筛选。
- 关键词和语言条件可组合使用，页面显示筛选后的项目数量。
- 筛选不会重新编排源站排名，也不会实时搜索 GitHub。
- 没有匹配项时提示调整关键词、语言或日期。

### 5.3 项目详情

详情弹窗读取当前来源、当前日期的项目快照，展示：

| 信息组 | 字段 |
| --- | --- |
| 基本资料 | 仓库全名、简介、GitHub 链接、语言、许可证 |
| 快照信息 | 榜单日期、采集时累计 Stars、快照采集时间 |
| 时间信息 | 项目创建、项目更新、最近代码推送、首次采集、最近采集 |
| 阅读内容 | README 原文，以及 Trending 可用的中文译文 |
| 质量提示 | 译文过期、翻译错误、旧数据回填提示 |

“项目更新”和“最近推送”分开展示，不能将更新时间直接理解为代码提交时间。首次、最近采集时间取自该快照保存的资料。

详情支持关闭按钮、点击弹窗外区域及 Escape 关闭。缺失的语言、许可证和时间有对应占位提示；无 README 时保留基本资料并显示空状态。

### 5.4 中文翻译

- 仅 Trending 采集调用翻译服务；需配置服务地址、模型与密钥。
- 未配置翻译时，仍可采集、查看原文。
- Trending 详情默认优先中文；没有中文译文时自动展示原文，中文按钮不可用。
- README 按块翻译，保护代码块、行内代码和链接，全部分块成功后才替换完整译文。
- 翻译失败时保留原文和已有译文；旧译文不匹配原文时提示可能过期。
- 当天翻译未完成的快照可基于已冻结原文补翻，不重新覆盖当天项目资料。
- Star 总榜不会触发翻译，其榜单快照和页面只提供原文。

翻译服务可能收费，结果可能有误译，用户可通过原文核对。

### 5.5 采集与调度

| 规则 | 当前行为 |
| --- | --- |
| 默认调度 | 两个来源均为北京时间每日 01:00，可分别配置小时 |
| 调度检查 | 开启自动调度时约每 30 秒检查一次 |
| 启动补采 | 当天到达配置时间后，检查并补采符合条件的未完成任务 |
| 自动重试 | 部分完成、失败或中断任务按距离最近任务开始时间至少一小时的条件重试，并遵守限流冷却 |
| 手动触发 | 不必等待每日调度时间；仍受当天完成状态、任务互斥和限流限制 |
| 并发限制 | 两榜共用采集锁，同一时间只运行一个采集任务 |
| 同日规则 | 沿用当天首次成员列表，成功记录不覆盖，补齐未完成项 |
| 跨日规则 | 生成新的日期记录，保留旧快照 |
| 页面状态更新 | 约每 4 秒轮询最近任务，任务结束后刷新列表 |

已完成、其他采集正在执行或处于冷却期时，触发请求被拒绝并显示原因。当前页面采集运行期间，按钮显示“采集中…”且不可重复点击。

任务的成功/失败数量是当前任务处理计数，不应直接当作新增入库数量；翻译失败的项目也可能已经保存原文资料。

## 6. 数据口径与历史规则

1. **Trending 的新增 Stars**：采用来源页面统计窗口内的值，不等于北京时间自然日的精确增长，也不是全站每日增长排名。
2. **Star 总榜**：按项目当前采集时的累计 Stars 排序，包含 fork，不排除归档仓库；受来源搜索索引与返回范围影响，不承诺穷举全站。
3. **累计 Stars**：页面显示所选日期采集时的数值，不是浏览当下的实时值。
4. **时间口径**：榜单日期按 `Asia/Shanghai` 归档；时间戳以 UTC 存储，页面时间按浏览器本地时区格式化。
5. **快照隔离**：两榜独立保存每日项目资料及 README。同一仓库可同时存在于两榜，两榜也可有不同的采集时间。
6. **历史保留**：成功快照不会被后续日期的资料覆盖。翻译未完成时可以补充翻译结果。
7. **旧数据回填**：标记为 `legacy_backfill` 的资料和 README 来自迁移时的最新内容，不能视为历史当日实况；页面显示提示。
8. **缺失历史**：停机或未采集日期无法事后恢复当时的真实榜单，日期列表不补造记录。
9. **历史数量**：调整 Top N 配置只影响后续采集，不裁剪已有日期的榜单。

## 7. 状态与异常处理

| 状态或场景 | 用户可见行为 | 处理规则 |
| --- | --- | --- |
| 加载中 | 列表或详情展示加载提示 | 等待请求完成 |
| 尚无数据 | 提示建立第一份快照 | 可手动触发或等待调度 |
| 无匹配项目 | 提示调整筛选条件 | 保留日期和筛选控件 |
| 列表加载失败 | 显示错误及“重新加载”按钮 | 可重试读取 |
| 正在采集 | 显示运行状态，禁用当前采集按钮 | 后台继续处理 |
| 采集完成 | 显示结果计数及结束时间 | 刷新列表 |
| 部分完成 | 显示失败计数及错误摘要 | 保留成功项目，可补齐 |
| 采集失败 | 显示错误摘要 | 保留已有数据，后续重试 |
| 采集中断 | 重启恢复后标记中断 | 按规则重试或手动补齐 |
| 状态查询失败 | 提示采集状态暂不可用 | 不据此认定任务已经失败 |
| GitHub 限流 | 提示冷却相关错误 | 两榜共享冷却保护 |
| 翻译不可用或失败 | 保留原文，显示对应状态 | 配置或恢复服务后补翻 |
| README 缺失 | 显示暂无 README | 不丢弃项目资料 |
| 搜索响应异常 | 任务失败 | 不使用不完整、重复或格式异常的结果更新榜单 |

## 8. 部署与运行边界

- 使用 Docker Compose 部署 Web、API、PostgreSQL 三个服务，详细步骤见 [项目 README](../README.md)。
- 默认 Web 端口为 `8080`；API 和数据库不发布宿主端口。
- 自动采集要求设备及服务持续运行；关闭自动调度后仍可手动触发采集。
- GitHub Token 可选；较多项目的采集建议配置，以减少匿名访问限流影响。
- 翻译地址、模型和密钥由部署人员配置，凭据只供后端使用。
- 当前无登录认证，能访问应用的人可以查看数据并触发采集，适用于可信网络。
- README 渲染进行 HTML 清洗、危险链接过滤和相对链接转换；不执行仓库代码。
- README 图片和外部链接可能仍依赖网络资源，不保证完整离线展示。
- 数据通过数据库卷持久保存；维护时需要备份，不能使用删除数据卷的操作代替普通停服。
- 当前采用单 API worker，不将多进程或高并发部署作为已支持能力。

## 10. 已知限制与文档依据

### 10.1 已知限制

- Trending 页面结构变化可能导致解析失效，需要维护采集逻辑。
- 页面底部说明写明“01:00”和“前 100 项”，目前不会随部署配置自动变化；修改调度或采集数量时，需要同步检查展示文案。
- Star 总榜标题中的 Top 数量取自该日期已保存的快照数；部分采集完成时，不能据此判断目标数量已经全部采集成功，应结合任务状态。
- 尚未定义经过压测验证的响应时间、容量或可用性承诺。
- 当前未实现用户行为统计，因此没有已验证的用户规模、使用率或满意度指标。

## 11. 新增：采集项目观察与测评

入口为 `/crawler-watch`。此模块保存爬虫、网页提取和数据采集领域的候选项目，支持自动发现、手动添加、持续关注及人工测评，独立于前述两张每日榜单。

| 功能 | 产品行为 |
| --- | --- |
| 自动发现 | 每天按固定主题及关键词搜索，合并高 Star 和最近更新候选，默认排除 fork 和归档仓库 |
| 手动添加 | 输入 GitHub HTTPS 仓库地址或 owner/repo，验证公开仓库后保存并关注 |
| 查看与筛选 | 全部、我的关注、待测评、已隐藏；支持名称/描述搜索和语言筛选 |
| 热度排序 | 默认近 7 天净增，也可按近 24 小时净增或累计 Stars 排序 |
| 持续监测 | 默认每 6 小时，支持立即更新；共享全局调度开关、互斥与限流冷却 |
| 项目详情 | README 原文、发现依据、更新时间、增长的实际观测区间及最近 100 次成功样本 |
| 测评档案 | 保存测评状态、可选 1–5 分和纯文本笔记；无账号隔离，同一部署共享 |
| 关注与隐藏 | 关注便于筛选；隐藏停止监测并保留历史，可恢复；活动项目上限 200 |

**热度规则：** 增长量是实际样本的差值。使用目标时间前最近且不超过 6 小时偏差的样本作为基准，无基准显示“积累中”，允许负增长；超过 12 小时未成功观测标记过期。首日可看累计 Stars，完整 7 天增长需至少积累 7 天有效样本。统计仅覆盖保存的候选项目，不是全站实时排名。

**运行与恢复：** 失败保留最近成功资料；重试接续当天成功的发现查询，并跳过本轮不足 6 小时的成功观测。长期失败项目不会永久阻止健康项目刷新。启动时恢复中断状态，自动任务需要设备与服务持续运行。当前无外部通知、自动评分、自动翻译或仓库代码执行。

**新增验收项：** 添加去重、公开仓库验证、容量限制、隐藏与恢复、测评持久化、历史样本、增长基准缺失/负增长/过期排序、任务互斥、限流接续及原有榜单兼容。设计与实现范围见 [模块设计](superpowers/specs/2026-10-14-crawler-watch-design.md)。
